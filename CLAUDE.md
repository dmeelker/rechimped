# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Toolchain

The GUI needs Rust ≥ 1.93 (gpui uses `slice::as_array`; `rust-version` in `rechimped/Cargo.toml` enforces it).

```sh
cargo build                                   # whole workspace
cargo run -p rechimped                    # desktop app (binary: rechimped)
cargo test                                    # all tests
cargo test -p rechimped lenient_times     # single test by name
cargo clippy --workspace --all-targets
TIMECHIMP_REFRESH_TOKEN=... cargo run -p timechimp-api --example smoke [-- --write]
```

Keep `cargo clippy --workspace --all-targets` free of warnings and errors: fix every one before committing, including ones that were already there, rather than leaving them for later.

The `smoke` example hits the real API; `--write` creates and then deletes a test time entry and mileage registration.

A recurring `note: did not finalize incremental compilation session directory … Access is denied` is harmless (Windows/Defender locking `target\debug\incremental`); delete that incremental folder if it sticks.

gpui crates are pinned to `=1.17.2` (`gpui-unofficial`, `gpui-platform-gpui-unofficial`), the version gpuikit 0.9 is locked against. Upgrading gpui means moving every `*-gpui-unofficial` crate in `Cargo.lock` together (`cargo update -p <crate> --precise ...`), or mixed versions fail to resolve.

## Architecture

Cargo workspace with two crates.

### `timechimp-api` — API client library
Client for TimeChimp's **undocumented internal** web API (`web.timechimp.com/api`, as used by app.timechimp.com); it may change without notice.
- `auth.rs`: `Authenticator` logs in against AWS Cognito with SRP (`srp.rs`, password never sent), handles SMS/TOTP MFA via `LoginOutcome::MfaRequired(MfaChallenge)`, and refreshes access tokens from a refresh token. Persisting `refresh_token()` lets apps skip the password.
- `client.rs`: `Client` (cheap to clone, `Arc<Authenticator>`) with one async method per endpoint. Report data (`query_time`, `query_mileage`) comes from a server-side grid and must be paged by the caller.
- `models.rs`: serde models; `NewTimeEntry` / `NewMileage` are the write payloads.
- `srp.rs` has unit tests against a pycognito-generated vector in `testdata/`.
- `error.rs`: `Error::is_auth()` says whether logging in again is the fix (Cognito `Rejected`, i.e. the credential errors listed in `auth::REJECTIONS`; login protocol errors; a 401 after a refresh) as opposed to network/server trouble (including other Cognito errors, `Error::Cognito`, such as throttling). Requests time out (`auth::http_client`: 10 s connect, 60 s total).
- Tests: `models.rs` decodes the JSON fixtures in `testdata/` (hand-written to the observed shapes, not captured responses; swap in scrubbed real ones when the API changes) and snapshots the `to_json` request bodies; `tests/client.rs` runs `Client` against a local HTTP server (`tests/common/mod.rs`, shared with `tests/auth.rs`) via `Client::with_base_url` and `Authenticator::with_access_token` (whose refresh URL is a closed local port, so a test never reaches AWS); `tests/auth.rs` runs the refresh, retry-after-401 and SRP + MFA login flows against a local server standing in for Cognito too, via `Authenticator::from_refresh_token_at` / `login_at` (all `#[doc(hidden)]`, for tests). An `Authenticator` and the `Client` built on it share one `reqwest::Client`; after a 401 the token is only refreshed if no parallel request did so already (`refresh_after_rejection`).

### `rechimped` — Rechimped, the gpui + gpuikit desktop app
One root entity, `TimeChimpApp` (`app/mod.rs`), holds the UI state (screen, tab, the `overlay`, the dropdown `menu`, effects) and a `Session` (`session.rs`): the client and everything of the logged-in user (base data, config, week, selection, history, report), with the data-only methods (selection, form options, timezone, week figures) unit-tested there. Logging out replaces the `Session` as a whole. Its behaviour is split over `app/`, one `impl TimeChimpApp` block per concern: `actions` (the `actions!` list), `auth` (login/logout), `loading`, `settings` (the Settings window), `nav` (tabs, days, selection, `on_key`), `time_form`, `trip_form`, `date_field` (the calendar), `save` (submit, presets, form errors), `delete` and `chart` (the billability chart); Whatever covers the main screen is one `app::Overlay` (`Detail`, `About`, `Chart`, `Form`, `Settings`, `Confirm`): `open_overlay` refuses a second one, `close_overlay` closes it and refocuses the main view, and `on_key` only has to match on it; `TimeChimpApp::form()`/`settings_form()`/`chart()` and `time_form()`/`travel_form()` (via `Form::time()`/`trip()`) reach the open one. Views change it only through those methods (`close_overlay`, `toggle_menu`, `close_menu`), not by assigning fields. `view/` implements `Render` for `TimeChimpApp`, one file per screen or tab (`login`, `chrome` for header/toolbar/footer (including the tab strip, `render_tabs`: underline only, since gpuikit's `Tabs` also fills the selected tab), `week`, `travel`, `report`, `popups` for details and forms, `settings` for the Settings window and About, `chart` for the billability chart) plus `widgets` for the shared building blocks.
- **Async**: reqwest needs tokio, gpui has its own executor. `TimeChimpApp::run` spawns the future on a global tokio runtime (`net::runtime()`), awaits the `JoinHandle` inside `cx.spawn_in`, and applies the result in a callback with `&mut Self, Window, Context`. Each `Session` has a unique `epoch`; `run` drops results that come back for an older one (and `busy()` only counts the current session's tasks), so nothing of a logged-out account lands on screen; `show_login` also aborts that session's loads (`cancel_loads`; saves and deletes are left to finish). Week loads also carry a generation counter (`Session::begin_week_load`/`is_latest_week_load`) so a response for a week already left is dropped. All network work goes through `run`.
- **Session state**: the day, week, report month and report, and the selection are private to `Session` and change only through its methods (`select_day`, `select_entry`, `set_report_month`, `apply_report`, `invalidate_report`, …). The base data (user, projects, project tasks, tags) is one `Option<Base>` read through `me()`/`projects()`/`project_tasks(id)`/`tags()`, and `entries()`/`travel()` and `client()` are read-only too; a login creates a new `Session` around its client (new epoch). Moving to another week empties `entries`/`travel` at once; a loaded `session::Week` carries its Monday, and `week_loaded()` / `report()` (None unless loaded for the month shown) let the views say "Not loaded" after a failed load instead of showing stale or empty data. `net` returns `session::Base`/`session::Week`, so the state model doesn't depend on the I/O module.
- **Keyboard**: browse-mode shortcuts are a single `on_key_down` handler (`TimeChimpApp::on_key`, which looks the key up in the pure, unit-tested `nav::browse_command` keymap) on the element tracking `self.focus`; it only fires while that element (not a form input) has focus. Forms, the Settings card and the login card are separate modal elements with key context `"Modal"`; the login card handles `Confirm`, the Settings card `Confirm`/`Cancel`, a form `Confirm`/`Cancel`/`CalculateDistance` plus the address, calendar and Recent picker actions.
- **gpuikit overrides** (`main.rs::bind_keys`, registered *after* `gpuikit::init` so they win at equal context depth): in the `Input` context Tab/Shift-Tab move focus instead of inserting `\t`, Enter → `Confirm`, Escape → `Cancel` instead of blurring. gpuikit inputs aren't tab stops by default; `forms::text_input` sets `tab_stop(true)` on the shared focus handle.
- gpuikit's input has no password masking, hence the custom `password.rs` field.
- Config: `%APPDATA%\rechimped\config.toml` (`store::config::load`; reread on reload; a starter file listing projects and non-`z_` tags is written when missing; an old `projects.toml` is renamed to it). The top-level keys `work_days` (`mon`…`sun`; full names work too; default Mon–Fri), `billable_goal` (percent, default 80), `hidden_projects` (project names; only written once something is hidden) and the `[hidden_tasks]` table (project name → task names, matched case-insensitively; keys are changed in place, emptied ones dropped) form `store::config::Settings` (`Session::settings`); they are edited in the Settings window ("Settings…" in the user menu; `app/settings.rs`, `view/settings.rs`, `forms::SettingsForm`, checked by `validate::settings`): a category list on the left (`forms::SettingsPage`: General, Projects, Tasks, Project tags; `show_settings_page` switches and focuses the page's first field, or the window's own `SettingsForm.focus` on pages without one, so Escape/Enter still reach it), the page on the right, and one Save for all pages. It writes them back with `store::config::save_settings` via `toml_edit`, changing values in place so the rest of the file and its comments stay. `billable_goal` drives the Week tab's billable bar and the report's colouring. Hidden projects (the Projects page, `forms::ProjectVisibility`: checkboxes for the active projects, checked = shown; hidden names matching no active project are kept on save) are left out of `Session::project_options` and the Recent picker only (`Session::is_hidden`): their entries still show everywhere, and editing or copying one still offers its project (`project_options`' `current`); a new time entry takes its default project from the latest entry whose project is offered. Hidden tasks (the Tasks page, `forms::TaskVisibility`: a project list on the left like Project tags, checkboxes for that project's active tasks on the right; unmatched names are kept on save; on this page and Project tags the projects hidden on the Projects page are listed last and dimmed, `forms::ProjectRow` + `order`, re-sorted on each page switch) are likewise left out of `Session::task_options` and the Recent picker only (`Session::is_task_hidden`, by name); the entry being edited or copied keeps its task, and so does a preset's (`task_options`' `keep`). The Week card's billable share is of the contract hours from TimeChimp (`domain::week::week_card`); leave (project "Intern", task "Verlof", `domain::week::is_leave`) is left out of its total and taken off its contract hours, so it doesn't count for the share either (the day cards still include it). The card's "% billable" link opens the billability chart (`app/chart.rs`, `view/chart.rs`, `Overlay::Chart`): the selected week and the 4 before it (`domain::week::CHART_WEEKS`, `weeks_up_to`), fetched afresh on open (`net::load_weeks`) and computed per week with the same `week_card` (`week_cards`); bars of divs against a goal line, a tooltip per week; any key, the backdrop or Close shuts it. The day strip shows only work days plus today and the selected day (`domain::week::shows_day`, `Session::shown_days`), and ←/→ on the Week tab skip the hidden days (`domain::week::step_day`); [ ] and the toolbar's ‹ › move a whole week. `[projects]` maps project names to the tag names they may use (`resolve_project_tags`, case-insensitive); while no project has any, every project offers all non-`z_` tags (`Session::tags_for`/`tags_configured`, which the time form, `kept_tags` and the Settings window go through), so new users needn't configure first; the Settings window's Project tags page (`forms::ProjectTagsForm` in `SettingsForm.tags`, plain data with the projects on the left and drawn `checkbox_box`es for the selected one's tags) edits it; Save writes only the projects changed (all of them on the first change while none is configured, so the others keep every tag) with `store::config::save_project_tags` (keys changed in place via `toml_edit`) and then rereads the config. The time form shows a project's tags as checkboxes (`TimeForm.tags`, rebuilt on project change); tags on an entry that the selected project has no checkbox for are kept untouched (`kept_tag_ids`, `Session::kept_tags`; recomputed when the project changes). `[[trips]]` (`store::config::TripPreset`: name, project, from, to, optional distance, return_trip, type as `business`/`home-work`, billable, notes) are preset trips and `[[time_entries]]` (`store::config::TimePreset`: project, optional task, notes, tags; no times) preset time entries, listed in the ▾ dropdown of the split "+ Add trip" / "+ Add time" button (`render_add`, `render_presets_menu`; time presets show notes over project); picking one opens the form for the selected day filled in (time presets resolve their names via `Session::resolve_time_preset` and fill the form like the Recent picker, `fill_time_form`); the form's "Save as preset" appends one as text (`store::config::append_preset`, generic over the `Preset` trait, so comments survive; trips are named from their notes or the addresses, time presets have no name and are told apart by project, task and notes). Each preset's × in that dropdown deletes it: it confirms via the shared delete dialog (`DeleteTarget::TripPreset`/`TimePreset`) and removes the block with `toml_edit` (`store::config::remove_preset`), keeping the rest of the file and moving the section comment above the first preset to the next one.
- Forms (`forms.rs`) are built from gpuikit `InputState` / `SelectState<i64>` / `Switch` entities. What they open with is worked out as plain data in `seed.rs` (`seed::time_form`, `time_fill` for the Recent picker and presets, `project_changed`, `trip_form`; unit-tested), and `app/time_form.rs` / `app/trip_form.rs` only turn that into entities; on submit `TimeForm::values` / `TravelForm::values` snapshot them into plain structs, which `validate.rs` checks and turns into requests or presets (no window needed, so it's unit-tested). Changing a time form's project replaces its task `SelectState` (selects can't change options in place).
- Delete confirmation uses gpuikit `DialogState`; popups and forms are `deferred` overlays from `TimeChimpApp::modal`. The overlay's `absolute().inset_0()` must not be wrapped in an unpositioned div, or it collapses to zero height. Status messages are gpuikit toasts (`cx.toast_manager()` must stay rendered in the root); the last error also stays in the footer (`TimeChimpApp.error`, next to the busy label) until the next successful load or info message.
- App icon: `assets/rechimped.ico` (a monkey face drawn by `assets/make-icon.ps1`; rerun it after changing the design), embedded as icon resource 1 by `build.rs` via `embed-resource` (needs the Windows SDK `rc.exe`); gpui loads resource 1 for its windows.
- Theme (`main.rs::theme`): Catppuccin Latte, TimeChimp orange accent, white button fill, and an enlarged `theme.controls.medium` rung (28px); all gpuikit controls size themselves from those metrics, so tune sizes there rather than per element. Status bars (day and Week cards) are `view::widgets::meter` in the colour of their figure (`hours_colour`/`goal_colour`): gpuikit's `progress` draws its Success variant in the accent colour.
- Buttons: gpuikit's `ButtonVariant` is only `Filled`/`Destructive`. Wrap secondary buttons in `view::widgets::pop(theme, button(..))` (outline + shadow); a screen's main action uses the custom `view::widgets::primary_button` (solid accent). Keep new buttons consistent with that. The toolbar starts with Today (a `pop` button, disabled while today / this week / this month is shown) and two borderless `view::widgets::nav_arrow`s, then a `period_title`; ‹ › step the period the title shows, a week on Time and Travel and a month on Report (`TimeChimpApp::step_period`), while ←/→ on the Time tab still step a day.
- Trip form From/To (`TimeChimpApp::render_address`): plain text fields (any address can be typed) with a suggestion list of `Session::saved_addresses` (`TravelForm.addresses`/`address_menu`, filtered by `domain::matching_addresses`). Typing opens it filtered with nothing highlighted, ↓ or the ▾ opens it unfiltered; ↑/↓/Enter/Escape are bound in context `AddressField > Input` and call `cx.propagate()` when there's nothing to do, so the next binding (Enter → `Confirm`, Escape → `Cancel`) still runs. Rows pick on mouse *down*; focus-out closes the list. gpuikit's `Combobox` was not used: its input is private, so it can't be a tab stop, be focused on open, or hold a free-typed address.
- Date field of both forms (`forms::DateField`, `TimeChimpApp::render_date`): a text field (YYYY-MM-DD can still be typed) whose calendar icon or ↓ opens gpuikit's `Calendar` (Monday first) in a `deferred` popup; a typed date shows in it. The **field keeps the focus** and drives the calendar via `Calendar::set_selected` (`move_calendar`): while it is open ←/→ move a day, ↑/↓ a week, PageUp/PageDown a month, Enter/Escape close it, all bound in `DateField > Input` and passed on with `cx.propagate()` when it is closed. Reason: gpuikit draws a focused calendar's focus ring as a filled shadow behind its transparent grid, so a keyboard-focused calendar turns solid accent; a click on the calendar hands focus straight back (`on_focus_in`). gpuikit's month buttons also draw invisible chevrons (colour set on the div, not the svg), so `render_date` overlays visible ones that let clicks through.
- Recent picker (new time entries only): `net::load_history` fetches the last 5 weeks on reload; `Session::apply_week` merges every loaded week into `Session.history`, and `domain::week::recent_items` groups it by project/task/notes. Picking replaces the form's project select together with its subscription (`TimeForm.project_sub`). ↑/↓/Enter in the filter are bound in context `RecentPicker > Input` (`main.rs`).
- Form tab order is paint order, so field order in `render_form` is the Tab sequence (time form: Start → End → Notes → Hours, on purpose).
- Dropdowns (user menu under the name in the header, holding Settings…, About Rechimped (version from `CARGO_PKG_VERSION`; `render_about` in `view/settings.rs`, closed like the chart) and Log out; presets under the ▾ of "+ Add time" / "+ Add trip"): `TimeChimpApp.menu: Option<Menu>`, each rendered as a `deferred` `menu_panel` inside its trigger's `relative()` wrapper plus one window-wide transparent backdrop in `render_main` (`render_menu_backdrop`) that closes it; any key closes it too. gpuikit's `context_menu` only opens on right-click, hence the custom one.
- Tables: `view::widgets::table_card` (Time, Travel) and `panel` (a `table_card` with a title row; Report) may shrink (`min_h_0`) and their rows go in `view::widgets::table_rows`, a plain `overflow_y_scroll` div, so a long table scrolls under its fixed column header; the page body itself no longer scrolls. Non-billable rows in the Time, Travel and Report tables have muted text on a lavender tint, apart from the grey header (`view::widgets::non_billable_bg`, hover via `row_hover_bg`); the Report's bars are green for billable rows, grey otherwise. Edit / Copy / Delete are icon buttons in the selected row only (`TimeChimpApp::row_actions`, a last column `ROW_ACTIONS_WIDTH` wide with an empty header cell).
- Travel tab: `net::load_week` sorts trips by (date, id), so `render_travel` groups consecutive rows per day under a header (the week's total km is in the toolbar title) and ↑/↓ follows screen order. Editing a trip (E / double-click / Edit) `PUT`s `mileage/{id}` via `Client::update_mileage`, which carries the approval statuses over from the original, as the web app does.
- Effects (`fx.rs`, state in `TimeChimpApp.fx`): gpui has no custom-shader hook, so they are built from its GPU primitives, redrawn per frame from elapsed time: aurora "orbs" are drop shadows with a huge blur (gpui's Gaussian shadow shader), ribbons are gradient-filled `PathBuilder` paths. The aurora and the login card's `glow_frame` run on the login screen; `sweep_bar` under the header sweeps once when `fx.sweep` is bumped (tab switch, week loaded) and loops while `busy`; F12 (`ToggleShowcase`, global binding) puts the aurora behind the main screen and shows the frame-time HUD. `Fx::begin_frame` (top of `render`) only requests animation frames in those states and honours `reduce_motion`, so the app stays idle otherwise; `end_frame` must stay the last child of the root, as its canvas measures CPU time per frame.
- Gaps/overlaps between consecutive entries of a day come from `domain::week::junction` and render as marker rows via `entry_rows_with_gaps` in the Week tab's entry list.
- Unit tests build API models with `test_support` (`entry`, `trip`, `project`, `task`, `tag`, `user`, `report_row`, `date`, and `base` for `Session::apply_base`).
- Modules besides the UI (`app`, `view`, `forms`, `password`, `fx`): `net` loads data (runtime, `load_base`/`load_week`/`load_weeks`/`load_history`/`load_report`); `domain` is UI-free logic with unit tests: `domain::time` (the lenient time parser: `9`, `930`, `12:30`; End also takes `+15`, `+1h`, `+1h30`, `+1.5h` = start + that duration, expanded on blur and at save; timezones; `parse_decimal`), `domain::week` (recent items, gaps, the Week card's figures, hours per day, shown days), `domain::report` (`Report::summary`); `store` holds the files: `store::config` (its I/O takes the path, so tests use a temp dir) and `store::token`, the session token at `%APPDATA%\rechimped\refresh_token` ( `TIMECHIMP_REFRESH_TOKEN` overrides it, and `TIMECHIMP_EMAIL` pre-fills the login email when no session supplied one).

## Checking UI changes

Running the app with a stored session talks to the real account. When testing, avoid saving or deleting unless asked; cancel dialogs with Esc.

To verify visually on Windows: start `target\debug\rechimped.exe`, post input with `PostMessage` to the process's `MainWindowHandle` (a `WM_LBUTTONDOWN/UP` on an empty spot first, so the window takes key input; then `WM_KEYDOWN/UP` with VK codes), and capture with `PrintWindow`. Don't use `SendKeys`: it types into whatever window has the foreground. Stop the app before rebuilding, since a running exe blocks the linker.
